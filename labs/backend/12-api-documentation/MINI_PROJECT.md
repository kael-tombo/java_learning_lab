# Mini Project: Api Documentation

## The assignment

This API documentation mini build produces a working farmers-market documented API you can run locally.
Scope stays deliberately small so every API documentation behavior remains observable.
Budget roughly one focused evening for the farmers-market documented API implementation.
Success means demonstrating API documentation judgment, not just compiling code.
Keep a lab journal noting each API documentation surprise encountered.
Acceptance checks define the edge, and no additions go past them.

## Parts you will wire

- OpenAPI description concept.
- Request and response examples.
- Error-schema documentation.
- Versioning notes in docs.
- Consumer try-it guidance.

## Build order

1. Describe stall, produce, and order endpoints in OpenAPI for the service.
2. Attach a realistic example to every operation.
3. Document the error schema with all status cases.
4. Note versioning policy beside each changed field.
5. Recruit one classmate to integrate using only the docs.

## Acceptance checks

- [ ] All 9 operations carry examples that actually validate in the solution.
- [ ] Error schema documents every returned status in the platform.
- [ ] Docs-only integration completes without asking the author.
- [ ] Changed fields reference the versioning policy.
- [ ] Spec lints clean with zero warnings.

## Stretch

Grow the project by adding one realistic complication you select.
Write the two-paragraph retro: which API documentation decision proved hardest.
Show the system to a peer armed with nothing but the acceptance checks.
