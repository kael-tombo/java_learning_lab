# Lab 04: Supply Chain (Cycle Counting) — VISION

## Where this lab takes you
From an annual shutdown count that discovered $2M of loss too late, to a cycle
counting programme that bounds the loss window and turns measurement into
prevention.

## The Arc
1. **Diagnose** — the annual count is a detection failure, not a control.
2. **Classify** — ABC by annual dollar usage, plus movement as a second axis.
3. **Frequency** — derive count intervals from materiality arithmetic.
4. **Schedule** — rotate by subinventory, counter, and time of day.
5. **Tolerance** — percentage *and* value cap, per ABC class.
6. **Capture** — barcode scanning removes transcription error.
7. **Code causes** — the mandatory step that actually prevents recurrence.
8. **Measure** — accuracy trend, not a count of counts.

## Milestones (checkable)
- [ ] M1: Run an ABC classification and confirm ~80% of value in ~20% of SKUs.
- [ ] M2: Add movement as a second dimension and find items ABC misses.
- [ ] M3: Derive a count interval from materiality for one high-value item.
- [ ] M4: Build the count schedule with rotation of location, counter, time.
- [ ] M5: Configure tolerance with both percentage and value caps per class.
- [ ] M6: Implement the scanner capture path and reject an unknown barcode.
- [ ] M7: Make root-cause coding mandatory and prove it cannot be bypassed.
- [ ] M8: Produce the accuracy trend and the cause Pareto.

## Anti-Goals
- Continuing annual counts and calling them a control.
- Using pure ABC and ignoring movement.
- Approving on percentage alone when the value at stake is large.
- Counting without mandatory root-cause coding.
- Treating shrinkage as a counting problem.
- Reporting counts performed as the success metric.

## The one-sentence thesis
Cycle counting is not about achieving perfect accuracy — it is about bounding
how long an error can hide, and turning every finding into a coded cause.
