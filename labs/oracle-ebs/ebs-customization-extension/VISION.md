# EBS Customization and Extension — Vision

## Where this lab takes you
From "it can't do that out of the box" to a customization you can upgrade past
— knowing which of CEMLI you actually need and what each option costs you later.

## The Arc
1. **CEMLI** — configure, extend, modify, localize, integrate.
2. **Configure** — profile options and setup: no code, fully reversible.
3. **Personalize** — form and OAF personalisations: smallest footprint.
4. **Extend** — public APIs, workflow, AME: the supported extension points.
5. **Modify** — only when no extension point exists, and at what cost.
6. **Localize** — legislation-driven changes with a distinct maintenance path.
7. **Integrate** — XML Gateway, business events, web services.
8. **Govern** — deciding which one, and recording the decision.

## Milestones (checkable)
- [ ] M1: For a given requirement, name the correct CEMLI option and justify it.
- [ ] M2: Implement a personalization and show how to remove it cleanly.
- [ ] M3: Extend a form through a public API rather than direct DML.
- [ ] M4: Configure an AME approval rule and test the escalation path.
- [ ] M5: Build a workflow process with a business event subscription.
- [ ] M6: Explain the upgrade cost of a modification versus an extension.
- [ ] M7: Publish a service through XML Gateway or a web service.
- [ ] M8: Write a customization decision record for a real requirement.

## Anti-Goals
- Customising before checking whether profile options already do it.
- Extending the Forms layer by replacing standard triggers.
- Modifying a standard object when an extension point exists.
- Shipping customization with no decision record and no owner.

## The one-sentence thesis
Every customization is a loan against your next upgrade — take the smallest one
that works, and write down why.
