# VISION — Data Governance (Deep): Policy, Access, and Accountability
> Where this lab takes you: from tagging data to enforcing decisions, proving
  effectiveness, and operating a program that survives an audit.

## The Arc
1. **Program** — scope, roles, accountability, and the operating calendar.
2. **Classify** — automatic classification with evidence, default-deny.
3. **Control** — access models, masking, purpose limitation, separation of duties.
4. **Enforce** — policy-as-code, CI gates, runtime enforcement, exceptions.
5. **Prove** — evidence, effectiveness testing, audit packs, metrics.

## Milestones (checkable)
- [ ] M1: write a governance operating model with roles, cadences, and owners.
- [ ] M2: build classification with stored evidence and default-deny.
- [ ] M3: implement RBAC + ABAC with purpose limitation on PHI access.
- [ ] M4: write a policy engine that gates CI and runtime, with expiring exceptions.
- [ ] M5: produce an audit pack with effectiveness tests, not just policy text.

## Anti-Goals
- A policy document that no system reads.
- Access reviews that sample 5% of a 2,400-person population.
- Compliance treated as a project with an end date.

## Interview Lens
- "How do you prove your access controls are effective?"
- "What happens when an exception expires?"
- "Who is accountable for a dataset nobody claims?"
