# VISION — Data Governance (Foundations): Ownership, Lineage, and Policy
> Where this lab takes you: from "ask the data team" to a governed platform
  where every dataset has an owner, a classification, and a deletion path.

## The Arc
1. **What** — data as an asset: owners, stewardship, accountability.
2. **Classify** — PII, PHI, PCI, sensitivity tiers, tagging.
3. **Lineage** — where did it come from, where does it go.
4. **Policy** — access, retention, deletion, residency, audit.
5. **Evidence** — proving compliance, not just claiming it.

## Milestones (checkable)
- [ ] M1: classify 20 fields across 5 tables and defend each tier.
- [ ] M2: build a lineage graph from a real DAG and answer 3 impact questions.
- [ ] M3: write a policy-as-code rule set and evaluate it against a real dataset.
- [ ] M4: implement a deletion request end to end and produce evidence.
- [ ] M5: produce an audit report an auditor would accept without a follow-up.

## Anti-Goals
- A classification spreadsheet that drifts from reality within a month.
- "No PII" as an assertion rather than a test.
- Policy documented in a wiki nobody reads during an incident.

## Interview Lens
- "How do you delete a customer's data across every copy?"
- "Who owns this table, and what happens if they leave?"
- "What is your evidence that access controls are effective?"

## 30-Day Plan
- Wk1 THEORY + EXERCISES L1-L6. Wk2 MINI_PROJECT with a lineage graph.
- Wk3 add policy-as-code and a deletion flow. Wk4 REAL_WORLD_PROJECT.
