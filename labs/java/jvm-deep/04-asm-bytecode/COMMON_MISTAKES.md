# Common Mistakes: Bytecode Generation

## 1. Compiling without the preview rig

```text
package java.lang.classfile does not exist
```

The entire API is preview-gated: every `javac` needs `--release 23
--enable-preview` and every `java` needs `--enable-preview` (JEP 466
second preview). Forgetting either half fails differently (compile
vs runtime gate) — pin both flags in every command, as lab 10's
verifier rig does.

## 2. Mutating elements in place

`MethodModel` and friends are immutable values. There is no setter
that renames a method or edits instructions — transforms select
(`builder.with(e)`) or withhold (drop) into a new builder. Code that
"edits" a model and re-emits the same object silently keeps the
original; snippet 3's withhold-to-delete is the only delete.

## 3. Hand-computing max_stack or frames

Wrapping builder output in manual `StackMapTable` attributes, or
trying to set `max_stack` directly, double-declares what the builder
derives and fails verification. Emit instructions and labels only
(`iload/iadd/ireturn`, `newLabel`/`labelBinding`/`if_icmpge`); the
builder tracks types as it emits — ASM's `COMPUTE_FRAMES` behavior
without the flag or the classpath analysis.

## 4. Assuming ASM API identity

`ClassReader`→`parse`, `ClassWriter`→`build`, visitors→transform
lambdas: names differ, the operation graph is shared. Porting ASM
examples method-for-method fails; porting them operation-for-
operation (parse/inspect/transform/emit) succeeds.

## 5. Forgetting defineClass verifies

Generated bytes are untrusted input to the linker like any other:
inconsistent output dies at `defineClass` with `VerifyError`, never
silently. The `magic intact` check in `GenerateAdd` is the cheapest
pre-screen, not a substitute — a correct magic with bad frames still
fails at define time, which is the enforcement that matters.

## 6. Version-stamping confusion

The *parser* reports versions (`model.majorVersion()`); the
*builder* defaults to current; explicit stamping is a separate
overload. Expecting `build` to inherit the parsed version, or
`parse` to normalize it, misreads both directions — snippet 5 proves
only the load-bearing direction (parse == raw bytes for `--release 17` → 61).

## 7. Filtering synthetic methods by accident — or not at all

`DropMethod` parses its own class, which contains a synthetic
`lambda$main$0` from the transform lambda itself. Asserting exact
method lists without the `lambda$` filter fails on your own
footprint; dropping without awareness of synthetics can delete
linkage (`BootstrapMethods` targets) while keeping callers.
