# How It Works: Bytecode Generation

## 1. Parse builds a view, not a copy

`ClassFile.of().parse(bytes)` walks the header/pool/tables (lab 01's
struct) and returns a `ClassModel` whose `methods()` iterator reads
the original array on demand. Asking for `thisClass()` or
`majorVersion()` touches a few bytes; iterating methods walks the
method table. Nothing is deserialized into mutable objects.

## 2. Inspection reads immutable elements

Each `MethodModel` exposes name (`methodName().stringValue()`),
type descriptor, flags, and attributes as values. The `<init>` entry
sorts with the rest in declaration order — the compiler emitted it,
so it is data like any method. Decisions (drop `main`? keep?) are
predicates over these values, taken before any builder exists.

## 3. Generation appends instructions to a builder

```java
cb.withMethod("add", MethodTypeDesc.of(CD_int, CD_int, CD_int),
        ClassFile.ACC_PUBLIC | ClassFile.ACC_STATIC,
        mb -> mb.withCode(cob -> cob.iload(0).iload(1).iadd().ireturn()));
```

Each call appends one instruction (`iload(0)` selects the `iload_0`
form automatically); `MethodTypeDesc.of(CD_int, ...)` declares
`(int,int)int`; flags declare access. `build` returns the finished
`byte[]` with magic, version, pool, and attributes materialized.

## 4. Derivation replaces hand computation

As instructions append, the builder tracks stack depth and local
types — the running state lab 03's verifier checks. At `build` it
writes the `max_stack`/`max_locals` it measured and emits
`StackMapTable` frames at the merges labels created. ASM needed
`COMPUTE_MAXS`/`COMPUTE_FRAMES` plus hierarchy access for this; here
it falls out of construction because types are known at emit time.

## 5. Control flow goes through labels

```java
Label elseL = cob.newLabel();
cob.iload(0).iload(1);
cob.if_icmpge(elseL);
cob.iload(1).ireturn();
cob.labelBinding(elseL);
cob.iload(0).ireturn();
```

Labels abstract byte offsets: the builder resolves jump distances
and derives the merge frame at `elseL`. The programmer states the
graph; the builder states the bytes — the same inversion as
parse-views over raw structs.

## 6. Transform selects, defineClass enforces

`transform(model, (b, e) -> ...)` replays every element; `b.with(e)`
keeps, returning without it drops. The output re-parses to a model
with `main` gone and everything else ordered as before. Loading via
`MethodHandles.lookup().defineClass(bytes)` runs the standard
verifier over generated bytes — the same gates as `javac` output,
with `magic intact` as the trivial pre-check and `VerifyError` as
the real one.
